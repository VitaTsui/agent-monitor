# 企业微信机器人接入指南

让用户在企业微信里用文字指令遥控自己的会话（查看 / 暂停 / 恢复 / 中断 / 终止 /
发布输入）。走官方合规通道（自建应用回调），不碰个人微信 hook。

个人身份即可：注册「未认证企业微信」，自建应用的收发消息对未认证组织可用
（有成员数上限，自用足够）。

## 一、企业微信后台配置（你来做）

1. **注册企业微信**：<https://work.weixin.qq.com> → 用微信扫码注册一个组织
   （个人也能建，主体填个人即可，不必认证）。
2. **建自建应用**：管理后台 →「应用管理」→「自建」→「创建应用」，
   设个名字和图标 → 记下 **AgentId**。
3. **拿 CorpID**：管理后台 →「我的企业」→「企业信息」最下方 **企业ID**。
4. **配「接收消息」回调**：进入刚建的应用 →「接收消息」→「设置API接收」：
   - **URL** 填：`https://monitor.vita-llm.com/monitor/wecom/callback`
   - **Token**：点「随机获取」或自定义，记下
   - **EncodingAESKey**：点「随机获取」，记下（43 位）
   - 点「保存」时企业微信会立刻请求上面的 URL 做验证 —— 需服务端已配好
     环境变量并重启（见下）后才能通过，所以**先做第二步再点保存**。
5. **可信 IP / 应用可见范围**：把应用可见范围设到你自己（或需要用的成员）。

## 二、服务端配置（我已实现，你填三项环境变量）

在 `/opt/agent-monitor/env` 里加三行（值来自上面）：

```
AM_WECOM_TOKEN=<第4步的Token>
AM_WECOM_AESKEY=<第4步的EncodingAESKey>
AM_WECOM_CORPID=<第3步的企业ID>
```

然后 `systemctl restart agent-monitor`。三项齐全机器人即启用；缺任一项则
`/monitor/wecom/callback` 返回 404（休眠），不影响其它功能。

配好后回企业微信第 4 步点「保存」，URL 验证应通过（服务端会校验签名 + 解密
echostr 原样返回）。

## 三、用户使用

1. 网页端「设置 → 账户 → 企业微信机器人」→「生成绑定码」（10 分钟有效）。
2. 在企业微信里打开该自建应用，发送：`绑定 <绑定码>`。
3. 之后可用指令：
   - `会话` —— 列出当前会话（带序号）
   - `设备` —— 列出名下设备
   - `暂停 N` / `恢复 N` / `中断 N` / `终止 N` —— 控制第 N 个会话
   - `发 N 内容` —— 向第 N 个会话发布一条输入
   - `帮助` —— 指令说明

   序号以最近一次 `会话` 列出的为准。

## 说明与边界

- 机器人只覆盖前台核心功能（会话监控与控制），**不含设置面板类操作**
  （设备管理 / 协助共享 / 安全防护 / 账户）——这些不适合 IM 遥控。
- 采用「被动回复」：收到消息后在 HTTP 响应里直接回一条加密文本，无需
  access_token，也就无需应用 Secret，最省心。
- 未认证企业微信自建应用有成员数上限（一般够个人/小团队）；要更大规模或
  主动推送（如会话状态变化提醒）需企业认证 + 用发消息 API（需 Secret）。

# 微信公众号机器人（个人订阅号，无需企业资质）

如果你只有**个人微信**、没有企业微信，用**个人订阅号**同样能做：你和别人都用
各自的个人微信关注这个订阅号、给它发指令，机器人在后台回复。完全官方合规、
零封号风险，指令与企业微信版完全一致。

## 一、注册与配置（你来做）

1. **注册订阅号**：<https://mp.weixin.qq.com> → 注册 →「订阅号」→ 主体类型选
   **个人**（免费，需身份证实名，一个身份证可注册有限个）。
2. **拿 AppID**：公众号后台 →「设置与开发 → 基本配置」→ **开发者ID(AppID)**。
3. **配服务器**：同一页「服务器配置」→ 修改配置：
   - **URL**：`https://monitor.vita-llm.com/monitor/mp/callback`
   - **Token**：自定义，记下
   - **EncodingAESKey**：点「随机生成」，记下（43 位）
   - **消息加解密方式**：选**安全模式**
   - 先做第二步（服务端环境变量）再点「提交」——微信会立刻请求上面 URL 验证。

## 二、服务端环境变量（我已实现，你填三项）

`/opt/agent-monitor/env` 里加：

```
AM_MP_TOKEN=<Token>
AM_MP_AESKEY=<EncodingAESKey>
AM_MP_APPID=<AppID>
```

`systemctl restart agent-monitor`。三项齐全公众号机器人即启用；缺任一项
`/monitor/mp/callback` 返回 404（休眠）。

## 三、使用

用户用个人微信**关注该订阅号**，然后：绑定码在网页端「设置 → 账户」生成，
公众号里发 `绑定 <码>`，之后指令同企业微信版（会话 / 设备 / 暂停 N / 发 N 内容 …）。

## 个人订阅号的边界

- **被动回复可用**：用户发消息→机器人即时回复，这正是本机器人所需，完全够用。
- **不能主动推送**：未认证订阅号无客服接口，做不了「会话状态变化主动提醒」，
  只能「你问它答」。要主动推送需公众号认证（¥300/年，个人订阅号无法认证，
  需服务号+企业）。
- 关注者收发消息本身不限量。
